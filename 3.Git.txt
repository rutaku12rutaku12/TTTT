[주요 용어]
    1.repository 리포지토리 : *저장소 코드들을 저장하는 하나의 저장소* 주로 프로젝트 단위
    2.commit 커밋 : 코드 수정 (로컬) 완료 * 로컬pc에만완료되고 온라인(웹깃허브) 에는 반영이 안된다.
    3.push 푸쉬 : 현재 로컬 코드를 깃허브(웹서비스)에 반영
    4.pull 풀 : 현재 웹서비스 버전으로 로컬 상태를 새로고침

[ 기존 저장소 가져오기 ]
    1.VSCODE 상단메뉴 -> [파일] -> 새창
    2.가운데 메뉴 (시작) 아래 [Git 리포지토리 복제]
        *PC에 깃 설치
        *VSCODE GIT 연동 로그인
    3.복제할 저장소 이름 선택/검색하여 [복제]

[깃허브 (웹[VCS]서비스)]
    -[학원 로컬 PC] 
    -[집 로컬 PC]
    -예)
        1. 학원에서 18시에 커밋과 푸시를 하면 웹 서비스 v1.1
        2. 집에서 20시에 pull(내려받기) -> 집 PC v1.1
        3. 집에서 22시에 커밋/푸시 > 웹서비스 v1.2
        4. 다음날 학원에서 9시 풀 > 학원PC v1.2
        5. 학원에서 18시 커밋 푸쉬 > 웹서비스 v1.3
        6. 집에서 20시 풀> 집 PC v1.3
    ---------------------------------------------------------------------    
    관례적으로 코드 작업하기 전에 'pull' 기능 이용하여 깃허브 버전 상태 최신화

[ 팀 깃 저장소 만들기 ]
    --------------초대 하는 사람 입장
    1. 새로운 폴더 생성
    2. 임의 파일 생성
    3. 소스제어 - > 해당 폴더(프로젝트) 를 깃허브 게시 하기
    4. 'public' 저장소 권장
    5. 팀 깃 저장소에 팀원 초대하기.
        (1) 깃 웹페이지 저장소에서 (가운데 위에)[Settings] 메뉴 클릭
        (2) 사이드바 메뉴 [ Collaborators ] 클릭
        (3) [ Add people ] 클릭 -> 초대할 사람 계정 검색
 
    ------------- 초대 받는 사람 입장
            (방법1) 깃 웹페이지 오른쪽 위 프로필사진 옆 알람
            (방법2) 깃으로 연동된 이메일 확인
            (1) 초대 승인
            (2) vscode 새창 열기
            (3) 소스제어 --> 리포지토리 복제 --> 초대받은 저장소 검색 --> 복제
    ------------- 모든 사람
        * 브랜치(=분기:독립적인 작업 흐름/공간) 생성
        * 각 팀원 1명당 하나씩 브랜치 생성 ( 서로 다른 브랜치 까지는 영향 없다. )
        (1) 브랜치 생성
            소스제어 --> ---(기타작업) --> (브랜치) --> [새분기/브랜치 만들기] -> 브랜치명 아무거나
